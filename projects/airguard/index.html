AirGuard

IoT-Based Hyperlocal Air Quality Monitoring and Alert System with Cloud Integration

ESP32 Hardware MQ135 Gas Sensor DHT22 Temp & Humidity Node.js / Express MongoDB Atlas React.js Dashboard Active Engineering Project

The Problem

Conventional ambient air monitoring stations are centralized, sparse, and expensive, often positioned kilometers apart. They provide city-wide averages that fail to detect localized pollution spikes caused by traffic congestion, industrial exhaust, or microclimate variations. Communities, schools, and workplaces lack affordable, actionable, real-time telemetry to protect individuals from sudden spikes in hazardous air pollutants.

The Solution

AirGuard bridges this gap by deploying an autonomous, low-cost IoT sensor node built around the ESP32 microcontroller. The unit samples ambient atmospheric parameters every few seconds, computes real-time Air Quality Index (AQI) indicators, transmits telemetry over Wi-Fi to a cloud-hosted Node.js backend, and visualizes immediate pollution trends on an interactive React dashboard.

System Architecture

The system employs a four-tier architecture designed for continuous telemetry, high availability, and decoupled data presentation:

1. Hardware Edge Node
  • ESP32 Microcontroller: Dual-core 240MHz Wi-Fi/Bluetooth MCU handling analog sampling and HTTP client payloads.
  • MQ135 Sensor: Calibrated gas detection for NH3, NOx, Alcohol, Benzene, and Smoke.
  • DHT22 Sensor: High-precision digital temperature and relative humidity sensing.
2. Ingestion & API Layer
  • Node.js & Express: High-throughput REST API endpoints for telemetry intake and device authentication.
  • Input Validation: Payload sanitization and anomaly boundary checking for aberrant sensor spikes.
  • Alert Trigger Engine: Evaluates incoming PPM and AQI against threshold levels.
3. Cloud Persistence
  • MongoDB Atlas: Time-series collections optimized for periodic sensor log indexing.
  • Aggregation Pipelines: Pre-calculates hourly and 24-hour moving averages for rapid charting.
  • Retention Policy: Efficient data archiving for historical longitudinal analysis.
4. Real-Time Web Dashboard
  • React.js (Vite): Fast, responsive single-page monitoring interface.
  • Recharts Telemetry: Live AQI gauge meters, historical trends, and pollutant breakdown.
  • Visual Warnings: Color-coded severity states (Good, Moderate, Unhealthy, Hazardous).

Technologies & Implementation

Every component was selected to balance cost-efficiency, accuracy, and developer ergonomics:

  • ESP32 Microcontroller: Offers onboard Wi-Fi (802.11 b/g/n), multiple ADC channels, and low-power sleep capabilities for battery or solar-assisted deployments.
  • MQ135 Gas Sensor: Analog resistance varies with hazardous gas concentrations; calibrated using standard clean-air baseline resistance (R0) curves.
  • DHT22 (AM2302): Provides temperature readings (-40°C to +80°C ±0.5°C) and relative humidity (0–100% ±2% RH) crucial for calibrating MQ135 temperature/humidity drift.
  • Node.js / Express REST API: Lightweight non-blocking I/O handling regular HTTP POST pings from distributed hardware nodes.
  • MongoDB: Schema flexibility allowing dynamic sensor payloads with geographic location tagging.
  • React Web App: Clean, component-driven UI with polling/event stream rendering for instantaneous situational awareness.

Implementation Status & Roadmap

Currently Implemented Features

Production Verified
  • End-to-end hardware sensor readout and analog-to-digital calibration on ESP32.
  • Wi-Fi connection recovery and telemetry payload transmission via JSON over HTTP REST.
  • Express API server receiving and validating environmental packets.
  • MongoDB time-stamped persistence with spatial metadata.
  • React web frontend displaying real-time AQI dials and historical line graphs.

Planned Future Enhancements

Roadmap / Planned
  • Companion Mobile App: Cross-platform Flutter mobile client with push notifications for instant hazardous AQI alerts.
  • Predictive ML Model: Deploying an LSTM time-series forecast model on AWS to predict next-day AQI spikes based on historical trends and weather patterns.
  • Mesh Networking: ESP-NOW mesh capability to interconnect multiple localized nodes across a campus without requiring dedicated Wi-Fi AP per node.
